1. Before you begin
  • Sign in with your administrator account at the Login page. Every screen in this manual requires you to be signed in.
  • The left-hand menu is grouped into sections:
    • Workspace — Events, Registration Forms, Post-event Surveys and Users (Users is shown to superusers only).
    • Advanced — Django Admin, the raw database screens (shown to staff accounts only). Use it only when this manual tells you to.
    • Help — User Manual (this page). It opens in its own tab, so you can keep it beside the screen you are working on.
    • Logout sits at the bottom of the menu, in red.
  • The button at the top of the menu, next to the PIKOM logo, collapses it to icons only. Hover over an icon to see its name, and click the button again to expand it. On a phone or tablet the menu is hidden; tap the menu button in the top bar to open it.
  • Permissions. Superusers see everything. Everyone else only sees events whose Campaign Team they belong to, and can only build forms and read registrations for those events. Being on the team is not the whole story, though: the + Add New button and the Edit pencil on Events, and the + New Registration Form button, only appear if a superuser has also given your account permission to create or change events and forms. If a button is missing or a page returns a permission error, ask a superuser.
“Event” and “campaign” mean the same thing. The menu and page titles now say Events, but a few labels still use the older word campaign — for example Campaign Team and Campaign dashboard.
Two steps, always in this order. The event comes first, then the registration form is attached to it. Creating the form first and attaching it later works, but until the link is made the form has none of the event’s details, banner or email wording.
2. How the pieces fit together
Object What it is Where you manage it
EventThe event itself: name, dates, description, organiser contact, banner, the team who runs it, theme colour and active/inactive status.Events

Registration formThe public page invitees fill in. It belongs to one event.Registration Forms
Form BuilderWhere you set the form’s banner, event details, email wording and the questions on that form.Registration Forms → Build form, or the event dashboard → Configure registration

The event details, agenda, maps and career directory are also shown to attendees in the attendee app, so whatever you enter here is what they see.

3. Part A — Create an event
Step A1Open the Events list

Click Events in the left menu. Each row is one event, with its Starts and Ends date and time (an event starts at 12:00 AM on its start date and ends at 11:59 PM on its end date), an Active or Inactive badge, and a set of action icons on the right. Click an event’s name to go straight to its registrations. Use Search and entries per page to narrow a long list.

Step A2Click + Add New

The Create event dialog opens on top of the list. Nothing is saved until you press Save, so you can back out at any point with Close.

Step A3Fill in the event details

The dialog has three groups: the name and dates at the top, Event information in the middle, and the team, colour and switches at the bottom.

Field What to enter
Event nameRequired. Appears in the Events list, on the dashboard and in registrant emails. If one event has more than one form, name them distinctly — e.g. … - REGISTRATION and … - SPONSORSHIP.
Start dateRequired. Click the field and choose the day from the calendar. There is no time to set — the event starts at the beginning of that day.
End dateRequired, and it cannot be before the start date. The event runs to the end of that day. This date is reused as the event date in the confirmation and reminder emails, so set it to the actual event day.
DescriptionA short introduction to the event. It appears on the event dashboard and in the attendee app, and on the public registration form if the form has no description of its own.
Organizer / contact name, Contact email, Contact phoneWho to contact about the event. Optional. They appear in the event details on the event dashboard. The attendee app does not show them.
Event bannerOptional. An image file under 5 MB. It is shown at the top of the public registration form unless the form has its own banner. The attendee app does not show it. A larger file, or one that is not an image, is rejected when you press Save with a “Something went wrong!” message — choose a smaller image and save again. When editing an event that already has a banner, the dialog says so; choose a new file only if you want to replace it.
‘Reply To’ EmailRequired. Where replies from registrants go. More than one address is allowed — separate them with commas and no spaces, e.g. pic1@mail.com,pic2@mail.com.
Campaign TeamThe users allowed to manage this event and its forms. Click the box and pick from the list; repeat to add several people.
Event Theme ColourAccent colour used on the public form and in registrant emails. Click Choose colour (or the swatch) and pick a colour in your browser’s colour picker. The chosen code is shown next to Selected:.
Enable or Disable QR Scanning PageLegacy QR submission flow. Leave off unless someone has specifically asked for it.
Event is activeOn (the default) = the event is live and shows the green Active badge. Turn it off to retire an event without deleting it.
Enable Or Disable Check In InfoOn (the default) = registrants are prompted for check-in information. Leave on for events you will check people in at.
Venue and event time are not in this dialog. Set them in Form Builder under the event details (Part C). Until then the dashboard shows Add venue and Add event time.
Step A4Check the dialog, then Save

Compare your entries against the example below, then press Save. The dialog closes and the new event appears in the list. If a required field is missing or the dates are the wrong way round, the field is outlined in red with a message underneath, and nothing is saved until you fix it.

Step A5Know the row icons

Once the event exists, its row carries the icons below. Hover over any icon to see its name. Which ones appear depends on whether a registration form is attached yet.

Icon Action
ChartCampaign dashboard — the event’s dashboard (Step A6).
EyeView registered participants — the registrations list for the attached form.
PencilEdit — reopens the same dialog you used to create the event, filled in with its current details. Only shown if you are allowed to change events.
GlobeOpen registration form — the live public page, in a new tab.
LinkCopy registration link — copies the public URL to your clipboard.
SlidersBuild / edit form — opens Form Builder (Part C).
QR scannerCheck-in scanner — the on-site scanning page for phones and Sunmi devices.
Plus boxShown instead of the four form icons when no form exists yet: “No registration form yet — click to create one”. It jumps straight to Part B with this event pre-selected.

Step A6The event dashboard

The chart icon opens the event’s dashboard. From top to bottom it shows:

  • The header — event name, dates, time, venue and an Event active or Event inactive label, with buttons for Configure registration (Form Builder), View attendees and All events. If no registration form exists yet, a Create registration form button appears instead.
  • Key figures — registrations (and how many are pending), approved, checked in, and whether registration is open or closed.
  • Event details — registration status, event time, venue, organiser contact and the description.
  • Event setup — shortcuts to Agenda, maps & booths, the Career directory and Attendees.
  • Charts — the registration funnel, registrations over time, top organisations and approval status. Until the first registration arrives, a message reminds you to share the registration link instead.
4. Part B — Create a registration form
Step B1Open Registration Forms

Click Registration Forms in the left menu — or click the plus-box icon on an event row, which opens this page with that event already selected for you.

Step B2Click + New Registration Form and fill it in

Click + New Registration Form at the top right. The Add New Registration Form dialog opens. Nothing is saved until you press Save.

Field What to enter
Form TitleRequired. Shown as the heading of the public page and in the forms list.
Public URL (optional)The readable part of the public address. Lowercase letters, numbers and hyphens only. Leave it blank and one is generated from the title. It must be unique — if another form already uses it, saving fails with a message telling you so.
Survey Start Date / Survey End DateRequired. Pick a date and time for each. They are kept as a record of when registration is meant to run, but they do not open or close the form — see the note below.
Survey DescriptionRich text shown to registrants under the title — venue, closing date, who to contact. The small toolbar handles bold, italic, underline, strikethrough, headings, lists, indents, text direction and text/highlight colour. It has no link button.
Select CampaignThe event this form belongs to. Pick it here: the event details and email wording in Form Builder depend on it. The list only offers active events you are allowed to manage, so an inactive event will not appear.
Active or Inactive the SurveyLeave on so the form can be opened.
What opens and closes registration. The public form accepts registrations whenever the form is Active and its event is active — whatever the start and end dates say. To close registration, switch the form (or the event) to Inactive; visitors then see the “Registration Closed” page.
More than one form on an event? Registrations made through the attendee app always go into the event’s newest active form. The public web links still go to whichever form they belong to.
Where is the real link? Don’t hand-build the public URL from this dialog. After saving, open Form Builder — the complete, correct link is displayed at the top under Shareable link, with a Copy button.
Step B3Save — five fields are created for you

When you save a new registration form, the platform seeds the core registrant fields so the form works end to end immediately:

Field Required by default
NameYes
Participant TypeNo — a fixed picklist (Delegate, Speaker, Sponsor, Organizer …). It is not shown on the public form; see the note below.
EmailYes
PhoneNo
OrganizationNo

These are identity fields. They feed the registrations list, the QR confirmation and the check-in screen, so they cannot be deleted — you can only make them optional or reword them.

Participant Type is set by your team, not by registrants. The public form never asks for it, so people who register online arrive with no participant type. Set it afterwards from the registrations list with the Participant Type toolbar button. Never mark Participant Type as Required — registrants cannot fill it in, so every public registration would fail with “Please complete all required fields: …” naming that field.
Step B4Row icons on the forms list
Icon Action
PencilEdit — reopens the dialog from Step B2.
SlidersBuild form — add and edit questions (Part C).
EyePreview form — see it as a registrant would; nothing is saved.
GlobeOpen public registration form — the live page.
LinkCopy public link.
QR scannerCheck-in scanner for the event day.
Exclamation markConsolidated report of the responses.
CopyClone form — copy its questions into another event. The fastest way to run this year’s event off last year’s form.

5. Part C — Set up the form in Form Builder

Form Builder has four blocks, top to bottom: the shareable link, the banner, the event details and email content, and the form fields.

Shareable link and banner

Copy puts the public link on your clipboard, Preview opens it without saving anything, Open live opens the real page. The banner sits at the top of the public form: PNG, JPG or WebP, up to 5 MB. Use Replace banner to swap it and Remove to clear it.

Event details

These lines appear in any email whose Include the event details block switch is on (see Email content below), and — if you switch the toggle on — at the top of the public form as well.

DateRead-only. Taken from the event’s end date. To change it, edit the event (Part A).
TimeFree text, e.g. 10.00 am – 1.00 pm.
VenueFree text, multiple lines allowed.
Dress codeFree text.
Additional info rowsExtra lines such as parking, agenda or lucky draw. Each row takes an emoji, a bold label, the text, and an optional link — when a link is given the text becomes clickable. + Add row adds more.
Show event details on this registration formPer-form toggle. On = the block above is also shown on the public page. It is off on a cloned form until you switch it on.

Press Save event details when done — this block has its own save button. Event details apply to the whole event, so every form on that event shares them. The time and venue you enter here are also what the event dashboard and the attendee app show.

Email content

This block is also shared by every form on the event. It has four tabs — three emails and one web page:

Thank-youEmail sent automatically as soon as someone submits the form.
QR confirmationEmail with the registrant’s QR code. Sent only when you send it — select registrants in the registrations list and use Send, or choose to send the QR when you register a walk-in. Approving someone does not send it by itself.
Attendance reminderEmail reminder before the event. Also sent only from Send in the registrations list.
Registration closedNot an email: the message shown on the public form while it is switched to Inactive. The page already shows a “Registration Closed” heading and the ‘Reply To’ contact; you write the text in between. Only the Event and Date buttons apply, and Open form shows the public page. Leave it blank for the default wording.

For each of the three emails:

  • Write a subject line and the body. The small buttons — Name, Reg no, Date, Event — drop in a placeholder that is filled per recipient. There is one set for the subject and one for the body.
  • Leave the subject blank to use the system default.
  • Two switches: show the banner image at the top, and include the event details block. On the Thank-you email the event details switch starts off.
  • Sign-off is the closing block — several lines allowed, with bold and colour.
  • Press Save email content, and use Preview to see the rendered email.
Form fields

The question list. Each row shows its number, its type (identity fields show Identity and a padlock), a Required tag, a List col tag when the answer is shown as a column in the registrations list, and the question text.

  • Drag the handle on the left to reorder; numbering updates itself.
  • Pencil edits a question, bin deletes it.
  • Identity fields (padlock) have no bin — mark them optional instead of removing them.
Add a question

Click + Add Question at the top right of the Form Fields block.

Field What to enter
Question textRequired. Basic HTML is accepted if you need a link or bold inside the label.
Help textOptional one-liner shown under the question.
TypeShort text · Long text (paragraph) · Dropdown · Single choice (radio) · Multiple choice (checkbox).
RequiredOn = the registrant cannot submit without answering.
Show in listOn = the answer becomes a column in the registrations list. Use it for the handful of answers your team sorts and filters on, not for everything.
Column header for the registrations listShort label for that column, up to 60 characters. Blank = the question text, truncated. Only used when Show in list is on.
ChoicesShown for Dropdown, Single choice and Multiple choice. One row per option; + Add choice adds more, the drag handle or the up and down arrows reorder, the red × removes. Add follow-up text attaches a free-text box to a specific option — useful for “Other, please specify”.
Include an “Other” free-text inputAdds a catch-all “Other” option with its own text box.
Max selectionsMultiple choice only. Caps how many boxes a registrant may tick; blank = no limit.

Press Save Question. The question appears at the bottom of the list — drag it into position. Cancel discards it.

6. Clone a form for a repeat event

When you run the same event again, don’t rebuild the form. Clone last year’s and point the copy at this year’s event — every question comes across with its type, choices, required flags and Show in list settings. Registrations do not.

Step 1Click the copy icon on the form’s row

Open Registration Forms, find the form you want to reuse, and click the copy icon — second from the right, just before the red bin.

Step 2Name the copy and choose its event
Field What to enter
New Form TitleArrives pre-filled as Copy of …. Replace it with the real name for this year’s event — the copy’s public URL is generated from this title, so a clean title gives a clean link.
Assign to CampaignThe event the copy belongs to. It arrives set to the original form’s event, so change it to the new event you created for this year. Only active events you are allowed to manage are listed.

Press Clone. The list reloads with the new form on it, ready to edit. Cancel leaves everything untouched.

Step 3Fix the things a copy can’t know
  1. The dates. Survey start and end are copied from the original, so they are still last year’s. They don’t open or close registration, but update them so the record is right: click the pencil on the new row.
  2. The public URL. It is generated from the new title. Open Form Builder and check the link under Shareable link before you share it.
  3. Event details and email wording. These belong to the event, not the form, so the copy shows whatever the new event holds — usually empty. Fill them in from Form Builder (Part C).
  4. Show event details on this registration form. This switch is not copied and starts off on the copy. Turn it back on in Form Builder if the public form should show the event details.
What a clone does and does not carry over
Copied Not copied
Every question — text, help text, type, choices, follow-up boxes, “Other”, max selections, Required, Show in list and its column header · the identity field setup · the form description · start and end dates · active status · the banner image, as its own separate file, so replacing it on one form never touches the other. Registrations and their answers · QR and check-in state · the Show event details on this registration form switch (it starts off) · the event details and email wording, which live on the event rather than the form.
Also useful for testing. To try a change without touching a form that is already collecting registrations, clone it, experiment on the copy, then delete the copy.
7. Test and go live
  1. In Form Builder, click Preview to check the page without writing any data.
  2. Then Open live and submit one real test entry yourself, so you can confirm the thank-you page and the Thank-you email. To check the QR confirmation email too, send it to your test entry from the registrations list.
  3. Check the entry landed in the registrations list, then delete it before you publish the link.
  4. Share the link from Copy — not a URL you typed by hand.
Where registrations arrive

Events → eye icon, or View attendees on the event dashboard. Each row is one registrant, with the registration number, approval status, check-in and QR state. Header counters summarise Total, Pending, Approved, Rejected, QR sent, Reminder and Checked in. From the toolbar you can register a walk-in, edit an entry, change status or participant type, and send QR codes or reminders.

Nothing after the Thank-you email is automatic. Approving a registrant does not email them. When you are ready, select the approved registrants and use Send for the QR confirmation, and again later for the attendance reminder. Online registrants also have no participant type until you set one here.
8. Pre-launch checklist
  • The event’s end date is the real event date — the emails read it from there.
  • ‘Reply To’ email is a mailbox someone actually watches.
  • Everyone who needs access is on the event’s Campaign Team.
  • The form is attached to the right event, and its start/end dates are filled in correctly for the record.
  • Banner uploaded; event details (time, venue) saved; the three emails and the Registration closed message read the way you want.
  • Participant Type is not marked Required.
  • Required flags are right, and the answers your team works from have Show in list on.
  • One test registration submitted, checked and removed.
  • The event is active and the form is Active — this is what opens registration.
  • You know who will send the QR confirmation emails, and when — they are not sent automatically.
9. Troubleshooting
Symptom Likely cause
“URL ‘…’ is already used by another form.”The Public URL you typed is taken. Choose another, or leave it blank to auto-generate.
Permission error opening Form BuilderYou are not a superuser and not on that event’s Campaign Team. Ask to be added.
The event does not appear in Select Campaign or Assign to CampaignEither the event is inactive — these lists only show active events — or you are not on its Campaign Team. Activate the event, or ask to be added.
No + Add New button or Edit pencil on EventsYour account is not allowed to create or change events. Ask a superuser.
Wrong date in the emailsThe date comes from the event’s end date. Edit the event, not the form.
Dashboard shows “Add venue” or “Add event time”They are not set yet. Fill them in under Event details in Form Builder and press Save event details.
Event details missing from the public pageShow event details on this registration form is off, or Save event details was not pressed.
Registrants see “Registration Closed”The form or its event is inactive. The start and end dates have no effect — switch both to active to reopen.
Registration still open after the end dateExpected — dates don’t close the form. Switch the form to Inactive.
Every public registration fails with “Please complete all required fields: …” naming the participant type questionParticipant Type has been marked Required, but the public form never asks for it. Edit that field in Form Builder and turn Required off.
Registrants did not get a QR codeQR confirmation emails are only sent when you use Send in the registrations list (or send one when registering a walk-in). Approving alone does not send it.
Saving an event shows “Something went wrong!”Often the event banner: it must be an image under 5 MB. Choose a smaller image and save again.
An identity field has no delete buttonBy design. Make it optional instead.
“Permission denied” or “Permission denied for that campaign” when cloningYou need rights over both ends: the first message means the form you are copying, the second means the event you are copying it into.
A cloned form shows last year’s datesExpected — dates are copied with the questions. Edit the new form and update them.
A cloned form doesn’t show the event detailsThe Show event details on this registration form switch is not copied. Turn it on in Form Builder.
